Euphoria LED Fix -- Quick Reference Document
=============================================

1. XamInputSetState signature -- Xenia emulator
   https://github.com/xenia-project/xenia/blob/master/src/xenia/kernel/xam/xam_input.cc
   
   XamInputSetState(DWORD user_index, DWORD unk, XINPUT_VIBRATION* vibration)
   
   - 3 parameters (not 6 as our original hook assumed)
   - 3rd param is XINPUT_VIBRATION*, not XINPUT_STATE*
   - Exported at ordinal 402
     https://github.com/xenia-project/xenia/blob/master/src/xenia/kernel/xam/xam_table.inc

2. LED mapping -- Santroller firmware
   https://github.com/Santroller/Santroller/blob/main/src/usb/device/xinput_device.cpp
   
   ```cpp
   if (subtype == DjHeroTurntable)
       euphoria_led = rumbleReport->leftRumble;
   ```
   
   Left motor (wLeftMotorSpeed) -> euphoria LED (0 or 255)
   Right motor (wRightMotorSpeed) -> rumble (0 or 255)
   
   XInputRumbleReport_t:
   https://github.com/Santroller/Santroller/blob/main/include/protocols/xinput.hpp
   
   wLeftMotorSpeed >= 32768  -> LED on
   wLeftMotorSpeed == 0      -> LED off

       if (c && c->isTurntable)

4. XINPUT_VIBRATION struct (Xbox 360 SDK via <xtl.h>)
   typedef struct _XINPUT_VIBRATION
   {
       WORD wLeftMotorSpeed;   // offset 0, left rumble / euphoria LED
       WORD wRightMotorSpeed;  // offset 2, right rumble
   } XINPUT_VIBRATION, *PXINPUT_VIBRATION;

5. Bug root cause
   Old hook declared 6 parameters and read bFrequency (register r7) for the
   LED state. But r7 is not a real parameter -- only r3-r5 are used by the
   3-param function. bFrequency was stale stack garbage, so the LED never
   triggered reliably. The real data was in the XINPUT_VIBRATION* (r5).
